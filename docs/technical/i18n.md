# Internacionalização (i18n) — PT-BR e EN

Base de tradução da saída de terminal (B2-06). Sem gettext, sem `.mo`, sem dependência
nova: catálogos são `dict` Python.

---

## 1. Peças

| Arquivo | Papel |
| :--- | :--- |
| `spectre_osint/core/i18n.py` | `t()`, `tn()`, resolução e persistência do idioma |
| `spectre_osint/core/locales/en.py` | catálogo inglês (`MESSAGES`), idioma de fallback |
| `spectre_osint/core/locales/pt_br.py` | catálogo português do Brasil (`MESSAGES`) |
| `tests/test_i18n.py` | paridade de chaves e placeholders, ordem de resolução, chaves usadas no código |

Idiomas suportados: `en` e `pt-BR` (`SUPPORTED_LANGUAGES`).

## 2. API

```python
from spectre_osint.core.i18n import t, tn

t("username.report", path="reports/x.html")   # "Full report: …" / "Relatório completo: …"
tn("username.unverified", 3)                   # usa "username.unverified.other"
tn("username.unverified", 1)                   # usa "username.unverified.one"
```

- Chave ausente no idioma ativo → texto em inglês; ausente em tudo → a própria chave.
  Uma lacuna de tradução nunca derruba o comando.
- Valores são inseridos com `str.format` e **nunca** reinterpretados como template.
  Placeholder sem valor devolve o template cru em vez de lançar exceção.
- Plural: `<chave>.one` quando `count == 1`, senão `<chave>.other`. `tn()` passa `count`.

## 3. Ordem de resolução do idioma

Primeira fonte válida vence:

1. flag global `--lang` (`spectre --lang pt-BR username …`) — valor não suportado é erro de uso (código 2);
2. variável `SPECTRE_LANG`;
3. config persistida: `{"language": "pt-BR"}` em `SPECTRE_CONFIG_FILE` ou, por padrão,
   `%APPDATA%\spectre\config.json` (Windows), `~/Library/Application Support/spectre/config.json`
   (macOS), `$XDG_CONFIG_HOME/spectre/config.json` ou `~/.config/spectre/config.json` (demais);
4. locale do sistema (`LC_ALL`, `LC_MESSAGES`, `LANG`, `LANGUAGE`, depois `locale.getlocale()`,
   que no Windows devolve nomes como `Portuguese_Brazil` ou `pt_BR`);
5. inglês.

Nas fontes 2–4 um valor inválido é ignorado (cai para a próxima). Qualquer variante de
português (`pt`, `pt_PT`, `pt_BR.UTF-8`) vira `pt-BR`; `C`/`POSIX` não indicam idioma.

`save_language()` grava a preferência preservando outras chaves do arquivo. Desde a Fase 3A
o comando `spectre config lang <pt_br|en>` a chama (e a tela Configurações do menu, na Fase 3B,
vai chamar a mesma função).

## 4. O que é traduzido

- Traduzido: saída compacta de `spectre username`, banner, barra de progresso, `spectre doctor`
  (padrão e `--all`: grupos, rótulos, valores, dicas e status), a mensagem de `--lang` inválido,
  `spectre config lang` e as mensagens de erro de `_cli_fail` (`cli.error.*`, por tipo de erro,
  nunca o texto da exceção — `cli/errors.py`).
- **Não** traduzido (dados e contratos): status (`CONFIRMED`, `LOGIN_REQUIRED`…), códigos de
  sessão, o JSON do `doctor --json`, relatórios e logs.
- Ainda em inglês (follow-up): seções detalhadas do `--verbose`, demais comandos
  (`email`, `domain`, `auth`, `cache`, `case`, `providers`…) e o texto do `--help` do Typer.

## 5. Como adicionar uma mensagem

1. Adicione a chave em **ambos** os catálogos, com os mesmos placeholders
   (prefixos em uso: `cli.`, `progress.`, `username.`, `doctor.`).
2. Use `t("prefixo.chave", ...)` com a chave **literal** no código — o teste
   `test_every_catalog_key_referenced_in_code_exists` procura literais com esses prefixos.
   Chaves montadas dinamicamente (`f"progress.{phase}"`) precisam de um conjunto fechado e
   de `has_message()` antes do uso.
3. Rode `pytest tests/test_i18n.py`: paridade de chaves, de placeholders e de pares
   `.one`/`.other` é verificada automaticamente.

## 6. Testes determinísticos

`tests/conftest.py` fixa `SPECTRE_LANG=en` e um `SPECTRE_CONFIG_FILE` temporário em todo
teste, para que o locale ou a config de quem roda a suíte nunca mude asserções. Testes de
resolução sobrescrevem ou removem essas variáveis explicitamente.
